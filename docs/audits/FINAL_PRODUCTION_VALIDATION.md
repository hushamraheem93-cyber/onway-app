## 0. حالة الوصول إلى الإنتاج

فحصت توفّر بيانات الاعتماد قبل البدء:

| المطلوب | النتيجة | كيف تحققت |
|---------|---------|-----------|
| `FIREBASE_SERVICE_ACCOUNT` | **غير متوفّر** | `env` = 0 نتائج |
| ملف `.env` للإنتاج | **غير موجود** | `ls .env` |
| ملف مفاتيح خدمة على القرص | **غير موجود** | `find / -name "*service-account*.json"` |
| خادم الإنتاج (Replit) | **غير قابل للوصول** | `curl` → `000` |
| `exp.host` (إرسال الإشعارات) | **غير قابل للوصول** | `curl` → `000` |
| أجهزة حقيقية (تاجر/سائق/زبون) | **غير متوفّرة** | تتطلب بشراً |

**الأثر:** كل ما يعتمد على Firestore/Storage/الإشعارات/الأجهزة = **Not Verified**.
**لكن** الخادم يعمل في وضع «التخزين في الذاكرة» عند غياب Firebase، فتمكّنت من تنفيذ **أكثر مما توقّعت** — بما فيه تسجيل زبون حقيقي وجلب المنتجات والسلة. كل ذلك منفَّذ فعلياً أدناه.

## 🔴 خطأ حرج وُجد وأُصلح في هذه الجولة

### `pm2 start ecosystem.config.js` كان يُنتج **خادماً ميتاً**
**الملف:** `ecosystem.config.js` · **الخطورة: CRITICAL** · **الحالة: ✅ أُصلح وأُعيد اختباره**

اكتشفته لأني **نفّذت أمر النشر الموثَّق فعلياً** بدل الاكتفاء بقراءة الملف.

**السبب الجذري:** الإعداد كان يعتمد على خيار `env_file: ".env"` في PM2. **إصدار PM2 7.0.3 يتجاهل هذا الخيار بصمت** — لا يصل أي متغيّر من الملف إلى العملية، فيخرج الخادم فوراً بالخطأ:
```
Error: JWT_SECRET environment variable is required but not set.
```
والأسوأ: **PM2 يعرض الحالة `online`** بينما التطبيق يدور في حلقة انهيار — فالعطل لا يُلاحَظ.

**الإثبات (تجربتان متقابلتان):**
| الحالة | النتيجة |
|--------|---------|
| `.env` موجود فيه `JWT_SECRET` + `env_file` مضبوط | `JWT_SECRET` **غائب** من `pm2_env` · حلقة انهيار · `curl :5000` = **000** |
| نفس الإعداد لكن `JWT_SECRET` مُصدَّر في الشِل | `curl :5000` = **200** |

**الإصلاح:** `ecosystem.config.js` ملف JavaScript ينفّذه PM2، فصار **يقرأ `.env` بنفسه** ويسلّم PM2 كتلة `env` مكتملة (يتعامل مع التعليقات والأسطر الفارغة والقيم المقتبسة مثل JSON حساب الخدمة). ترتيب الأولوية: الافتراضيات < `.env` < متغيّرات الشِل — فتبقى Replit Secrets تعمل كما هي. وعند نقص متغيّر مطلوب تظهر رسالة صريحة بدل الانهيار الصامت.

**إعادة الاختبار بالأمر الموثَّق حرفياً — نجح:**
```
pm2 start ecosystem.config.js
  status: online · restarts: 0
  JWT_SECRET loaded: YES · NODE_ENV=production · PORT=5000
  GET /api/categories -> 200      GET / -> 200
  kill -9 -> أعاد التشغيل تلقائياً -> 200
  حذف .env -> رسالة "Missing required environment variable(s): JWT_SECRET"
```

> **لولا هذا الفحص لكان أول نشر على VPS ينتهي بخادم لا يعمل.**

هذه ليست تفاصيل ثانوية — إنها **التطبيق نفسه**. منصّة توصيل لم يمر فيها طلب واحد كامل من طرف إلى طرف، ولم يُتحقَّق فيها من حساب مالي واحد بأرقام حقيقية، **لا يجوز فتحها لجمهور حقيقي**. وخطأ PM2 الذي وجدته للتو دليل عملي: عيوب قاتلة تختبئ في المسارات غير المُشغَّلة.

### شروط التحوّل إلى READY (كلها إلزامية)

1. **`node scripts/production-validate.mjs`** على خادم الإنتاج ← كل البنود PASS
   *(يغطي آلياً: Firestore، حاوية Storage، رفع صورة حقيقية والتأكد أنها ليست Base64، الفهارس، رموز Push)*
2. **دورة طلب كاملة بثلاثة هواتف حقيقية** ← الاختبارات 10–18
3. **التحقق من الأموال (#17)** ← الرصيد صحيح، **وإكمال نفس الطلب مرّتين لا يضاعف الرصيد**
4. **وصول إشعار فعلي** للزبون والتاجر والسائق
5. **نشر الفهارس**: `firebase deploy --only firestore:indexes`
6. ضبط `ALLOWED_ORIGINS` · التأكد أن **`DEV_MODE` غير مفعّل في الإنتاج** (وإلا `0000` يعمل!) · `JWT_SECRET` عشوائي جديد
7. **إلغاء رمز GitHub الذي كُشف سابقاً في المحادثة**
