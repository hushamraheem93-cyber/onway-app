# تقرير تنفيذ Sprint 1 — OnWay

**المستودع:** [hushamraheem93-cyber/onway-app](https://github.com/hushamraheem93-cyber/onway-app) [1]  
**الفرع المفحوص:** `main`  
**حالة التسليم:** التعديلات موجودة في نسخة العمل المحلية فقط. لم يتم تنفيذ `commit` أو `push`.

## ملخص التنفيذ

تم تنفيذ نطاق Sprint 1 الخاص بإدارة الحسابات الإدارية المتعددة، والأدوار والصلاحيات RBAC، وربط هوية المشغّل بسجل التدقيق، وحماية العمليات الإدارية الحساسة. حافظ التنفيذ على مسار JWT وCookie/Bearer الحالي، وعلى منطق الأعمال المالي ومعرّفات المحافظ والدفتر والتسويات دون تغيير.

أصبحت الجلسة الإدارية تحمل `adminId` و`username` و`displayName` و`role` و`permissions` ضمن Claims موقعة. ويعتمد الخادم على هذه الهوية في التفويض والتدقيق بدل أي قيمة يرسلها العميل داخل body. كما تم إبقاء الجلسات القديمة قابلة للتحقق على مستوى JWT، لكنها لا تمنح وصولًا لمسارات RBAC حتى يعيد المشغّل تسجيل الدخول ويستلم جلسة هوية جديدة.

## ما تم تنفيذه

| المجال | التنفيذ |
|---|---|
| Admin Users | إضافة مجموعة `adminUsers` backend-only، مع إنشاء وتعديل وتفعيل وتعطيل وعرض المستخدمين، والتحقق من الاسم وكلمة المرور والدور، ومنع تعطيل أو تخفيض آخر Super Admin. |
| الأدوار | إضافة `super_admin` و`operations_admin` و`finance_admin` و`support_admin` و`catalog_admin`. |
| الصلاحيات | إضافة قاموس صلاحيات dot-separated، مع wildcard محصور في `super_admin` وباقي الأدوار بصلاحيات صريحة. |
| Backend Authorization | إضافة حدود RBAC مركزية لمسارات `/api/admin/*`؛ المسار غير المعروف يفشل مغلقًا بـ 403 لغير Super Admin. |
| الترحيل | أول دخول ناجح ببيانات `ADMIN_USERNAME`/`ADMIN_PASSWORD` ينشئ أول Super Admin مع bcrypt ويعطّل fallback المشترك بعد وجود أول Admin User. لا تُحذف وثيقة الاعتماد القديمة خلال هذه الجولة. |
| Google Admin | ربط مسار Google بهوية Admin User، مع bootstrap لأول Super Admin في حالة عدم وجود أي Admin User. |
| Audit Log | إضافة `actorId` و`actorUsername` و`actorRole` و`resourceType` و`resourceId` و`before` و`after`، وإضافة تنقية recursive تمنع حفظ كلمات المرور والرموز والأسرار ومفاتيح API. |
| Audit API | إضافة فلاتر الفاعل والإجراء والمورد والتاريخ وpagination مع الحفاظ على فلاتر `targetType` و`targetId`. |
| المال والتسويات | تمرير هوية Admin الموقعة إلى approve/reject/complete والتعديلات المالية، مع تسجيل snapshots قبل/بعد دون تغيير الحسابات أو المعرفات. |
| Admin Web | إضافة قسم «المشرفون والصلاحيات» لإنشاء وتعديل وتفعيل وتعطيل الحسابات وعرض مصفوفة الأدوار. أضيف escaping مناسب للعرض وتمرير المعرفات إلى onclick عبر `JSON.stringify`. |
| Admin Mobile | تحميل هوية الجلسة والصلاحيات من `/api/admin/session` وتصفية التبويبات حسب الدور، مع إبقاء 401 handler والـ offline behavior وعدم اعتبار انقطاع الشبكة تسجيل خروج. |
| Firestore | إضافة قاعدة صريحة تمنع القراءة والكتابة المباشرة لمجموعة `adminUsers`، كما هو الحال مع `adminConfig`. |

## مصفوفة الأدوار

| الدور | النطاق الرئيسي |
|---|---|
| `super_admin` | كل الصلاحيات، بما فيها إدارة Admin Users والأفعال عالية الخطورة. |
| `operations_admin` | الطلبات والتشغيل والتوصيل والتعيين والسائقون والتجار والدعم والإشعارات التشغيلية. |
| `finance_admin` | التقارير المالية والدفتر والتسويات والموافقة والرفض والإكمال والتعديلات المالية والمحافظ والعمولات. |
| `support_admin` | قراءة سياق الطلبات والعملاء والتجار والسائقين وإدارة الدعم. |
| `catalog_admin` | المنتجات والفئات والبنرات والعروض والكتالوج ومحتوى الموقع. |

التفويض الفعلي يتم في Backend، وليس في الواجهة فقط. مثال: `operations_admin` لا يستطيع تنفيذ `settlements.approve`، بينما يستطيع `finance_admin` ذلك؛ كما أن مسارًا إداريًا غير مضاف إلى خريطة الصلاحيات لا يُفتح تلقائيًا.

## الترحيل والتشغيل

يجب أن تكون إعدادات Firebase/Firestore متاحة للخادم عند التشغيل الفعلي. في أول تسجيل دخول ناجح بالحساب المشترك القديم، ينشئ الخادم سجل Admin User أوليًا بدور `super_admin` ويصدر جلسة تحمل الهوية الجديدة. بعد ذلك يُرفض تسجيل الدخول بالحساب المشترك القديم، وتصبح إدارة الحسابات من قسم «المشرفون والصلاحيات». لا يعيد Sprint 1 كتابة أو حذف السجل المالي أو وثيقة الاعتماد القديمة، ولا يغير معرفات `walletId` أو `ledgerId` أو `accountId` أو `settlementLedger`.

## الملفات الرئيسية

تم تعديل ملفات المصادقة والخادم والعميل والقالب وقواعد Firestore والاختبارات القائمة. وأضيفت الوحدات التالية:

- `server/adminTypes.ts` لتعريف الأدوار والصلاحيات وعمليات مطابقة الهوية.
- `server/adminRbac.ts` لتخزين Admin Users والترحيل ومسارات الإدارة.
- `server/adminAuthorization.ts` لخريطة التفويض المركزية والـ fail-closed boundary.
- `tests/unit/sprint1-rbac.test.mjs` لاختبارات Sprint 1 الجديدة.
- `Sprint1_AUDIT_FINDINGS.md` لخريطة التدقيق قبل التنفيذ.
- `Sprint1_RBAC_DESIGN.md` للتصميم التفصيلي ومصفوفة الأدوار.
